# AUX3 一键起飞与 0.8 m 悬停

后续更新已接入BH1750和遥控器蜂鸣器，当前完整操作见[BH1750半自动说明](BH1750半自动检测与3秒悬停说明.md)。本文保留前次起飞逻辑说明；光源任务锁定窗口内的遥控规则以新说明为准。

更新：2026-10-25。允许误差已按用户最新要求调整为±0.2 m，最终目标仍为0.8 m。直接修改现有 `02主控源码`，沿用原来的 STM32F103C8、NRF24L01 遥控、I²C 激光光流模块、姿态 PID、光流位置控制和电机混控。原文件备份在 `04_编译与验证/AUX3_一键起飞_20261025/原始源码`。

## 已实现的操作

1. 将飞机水平静置于地面，油门最低，方向和偏航摇杆回中。高度测量必须有效且稳定至少约 0.5 秒，探头离地应在 40～250 mm。
2. 按左摇杆下方上面的 **AUX3**（遥控器标注“按钮通道3”，无线数据对应第7通道）。程序检查条件后自动解锁，先用约 0.8 秒缓慢转动电机，再以每秒约 0.2 m 的目标变化率垂直升到 **0.8 m**。
3. 油门保持最低即可自动起飞和定高，不必先推油门。自动模式不会执行原程序的“低油门下降”分支，也不会把回中时的高度覆盖成新目标。
4. 离地超过约 0.2 m 后启用原光流位置保持；爬升阶段不接受水平移动指令。达到 0.6～1.0 m、垂直速度不超过 0.08 m/s 且光流有效，连续约 1 秒后进入 `AUTO_HOVER`，持续固定 0.8 m 目标。悬停阶段允许用右摇杆调整水平位置，回中后保持新位置。
5. 重复按 AUX3 不会重启起飞过程。需要正常降落时，把油门推到中间保持至少 0.25 秒，再拉回最低并保持约 0.15 秒；程序按约 0.15 m/s 的目标变化率下降，在起飞时记录的近地高度确认落地后上锁。
6. 保留原来的油门最低、偏航向左的紧急上锁动作。自动模式中的大倾角保护也会生效。

高度指的是测距探头到地面的垂直距离，并进行了横滚/俯仰余弦补偿。起飞时的地面读数用于降落，不会额外加到 800 mm 目标上。±0.2 m 是控制目标和软件到位判据，实机精度尚未验证。

## 红蓝灯告警

按本次确认的灯色和原源码位置注释：

| 情况 | 输出 | 接口与 PWM |
| --- | --- | --- |
| 高度持续低于 0.6 m | 后方两颗红灯闪烁，前灯灭 | LED3＝PB0/TIM3_CH3；LED4＝PB1/TIM3_CH4 |
| 高度持续高于 1.0 m | 前方两颗蓝灯闪烁，后灯灭 | 右前 LED1＝PA6/TIM3_CH1；左前 LED2＝PA7/TIM3_CH2 |
| 测距失效等故障 | 前蓝、后红交替闪烁 | 四路 LED |

越界持续约 150 ms 才触发，闪烁亮灭间隔约 201 ms。告警恢复采用 20 mm 回差，回到约 0.62～0.98 m 后清除，减小边界抖动。0.6 m、1.0 m 本身不算越界。正常初始爬升和正常降落不触发低高度告警；爬升首次达到 0.6 m 后开始监视越界。告警优先于原来的飞行模式灯。

本次按照用户指定实现 LED 高低提示。现有资料只确认了遥控器上的蜂鸣器，没有机载蜂鸣器引脚定义；本版没有声响输出，也没有把遥控器蜂鸣器当作机载告警。若验收仍要求声光同时提示，声音部分仍需补齐。

## 模块损坏期间的行为与恢复

当前模块损坏，不能用这版软件证明已达到 0.8 m±0.2 m；实飞前必须恢复有效测距。零值、超出 40～4000 mm、通信失败不会刷新有效时间戳，未满足连续有效测距条件时拒绝一键解锁。程序也无法仅凭正常范围内的恒定数字，识别所有“卡住不变”的硬件故障。

协议沿用 8 位 I²C 地址 **0xC4**、寄存器 **0x33**、5 字节帧；没有更换传感器接口。协议图片明确写高度输出单位为 **cm**，因此默认在驱动入口乘 **10**，内部统一为 mm。旧代码虽然按 mm 使用，却没有做这一步，原资料存在冲突；当前默认值是依据协议作出的选择，还需要模块恢复后用尺子核实：

| 尺子参考距离 | 若 `flow_raw_height` 约为 | `FLOW_HEIGHT_MM_PER_UNIT` 应设为 |
| --- | ---: | ---: |
| 0.8 m | 80 | 10（当前默认） |
| 0.8 m | 800 | 1 |

在 `02主控源码/HAL/auto_flight_config.h` 修改后重新编译。还应核对 0.2 m、0.5 m、0.8 m、1.0 m，避免量程和偏移误判。没有用固定假高度绕过损坏模块。

短时无效帧会暂停高度积分并保持上一输出；连续失去有效测距超过约 120 ms 时，尚未确认离地则中止并上锁。已确认离地时进入 `AUTO_RANGE_FAULT`，退出高度和光流闭环、保持最后一次总油门，等待人工接管或紧急上锁。保持总油门无法保证高度，传感器恢复也不会自行继续任务。

人工接管：自动飞行时按 AUX1 请求接管，再把实体油门调到当前自动油门附近；匹配后转回原手动模式，避免从低油门瞬间接管。范围故障会自动发出同样的接管请求。匹配关系为 `200 + 0.45 × (遥控油门 - 1000)`，在调试器观察 `auto_flight.throttle` 和 `auto_flight.takeover_pending`；没有固定“回中即匹配”的假设。原遥控失联停机策略保留，计时改成真实约 3 秒，并在中断内检查。

如果高于约 0.2 m 后连续约 2 秒无法获得有效光流，程序进入下降流程，而不会把无位置反馈当成已经稳定悬停。未检测到离地超过约 5 秒会中止；爬升超过约 15 秒仍不满足悬停条件则请求降落。

## 为减小高度误差所做的处理

- 固定 800 mm 最终目标，缓慢改变目标和垂直速度指令，避免一步跳变。
- 三点中值和低通滤波，抑制单帧尖峰；速度使用测距差分和低通，避免沿用旧估计中的未统一加速度单位。
- 沿用原高度内环 `kp=1.2、ki=0.04、kd=0.085` 和外环 `kp=1.2`；自动高度外环使用限速的比例环，内环微分作用于测量，减小目标改变时的冲击。
- 自动高度内环增加积分限制、饱和时停止继续积累和总油门限幅。初始悬停总油门仍采用原程序的 500；需按实际机重、电池与螺旋桨实测调整。
- 先采集本周期测距，再计算高度和位置控制；无效数据不更新控制反馈。

没有凭空替换一套“已整定”PID。模块恢复后先记录高度、速度、总油门和目标曲线，再调整悬停基值、增益与滤波，才能确认是否达到 ±0.2 m。

## 源码入口与调试变量

| 入口 | 内容 |
| --- | --- |
| `HAL/auto_flight.c`、`.h` | 起飞、固定高度、悬停、降落、接管、故障和告警状态 |
| `HAL/auto_flight_config.h` | 高度、误差、速度、油门、单位、按键类型和灯色映射 |
| `HAL/remote.c` | AUX3 通道、包验证、自动/手动解锁协作 |
| `HAL/control.c` | 自动高度分支、原光流保持、电机入口和大倾角保护 |
| `HARDWARE/flow.c` | 测距单位转换、有效性、最近有效时间和原光流解析 |
| `HARDWARE/LED.c` | 红低、蓝高及故障灯优先级 |
| `USER/scheduler.c` | 6 ms 测距与高度任务，24 ms 光流任务，3 ms 姿态与电机任务 |

观察 `flow_raw_height`、`VL53L01_high`、`flow_height_valid`、`flow_valid_samples`、`flow_last_valid_tick`、`auto_flight`、`ALL_flag`。`SysTick_count` 每个计数代表 3 ms。

`auto_flight.state`：0 待机、1 电机缓起、2 爬升、3 悬停、4 降落、5 测距故障。错误枚举见 `auto_flight.h`。

默认认为 AUX3 与原遥控器 AUX1 一样，每次按下在 1000/2000 间切换。若更换遥控器后 AUX3 是按住为 2000、松开为 1000，将 `AUTO_AUX3_LATCHED` 改为 0；两种输入方式均有模拟检查。上电初始电平只用来建立基准，不会触发起飞。

## 构建与验证

测试和编译入口在 `04_编译与验证/AUX3_一键起飞_20261025/`：

```powershell
python .\04_编译与验证\AUX3_一键起飞_20261025\verify_auto_flight.py --cc C:\mingw64\bin\gcc.exe
python .\04_编译与验证\AUX3_一键起飞_20261025\build_arm.py
```

`build_arm.py` 默认使用本机已安装的 Arm Compiler 6.23；其他安装位置用 `--compiler-bin` 指定。使用本项目自带 STM32 头文件和启动文件直接构建，不要求先安装旧版 AC5 或设备包。为支持 AC6，`StartUp/core_cm3.c` 增加了四个栈指针函数的 clang 分支；原 AC5 分支保留。原 Keil 工程已加入新源文件。

另修正了 `CONFIG/I2C.h` 的读取宏括号：旧写法在 `!SDA_read` 中会先做逻辑非再按位与，无法正确检查 SDA 拉低；现已用对应主机检查覆盖。构建日志仍有原 `MATH/filter.c` 中未被当前工程调用的 `MovMiddle` 复制长度警告，以及旧汇编器弃用提示，日志完整保留。

实际 C 源码的主机检查覆盖两种高度单位/按键配置、按键启动基准、低油门自动起飞、固定目标、正常降落、测距零值和断线、地面测距失效、颜色告警和阈值端点、遥控坏包与失联、人工接管、大倾角、光流失效、原手动模式和 I²C 读取宏。简化垂直动力学模拟只用于检查控制趋势，不能代表真实飞行精度。

全工程编译和链接输出 `arm_build/mini_aux3.axf`、`mini_aux3.hex`、`mini_aux3.bin`，另有 map、完整日志、源文件哈希、固件哈希和检查 JSON。**没有连接、烧录或启动实机。** 最终检查数量与构建结果以对应 JSON 为准。
