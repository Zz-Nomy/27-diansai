## 操作流程

1. AUX3 一键起飞的操作沿用[原说明](AUX3一键起飞与0.8m悬停说明.md)。自动模式固定高度目标仍为 800 mm，允许范围 600～1000 mm。
2. 进入稳定悬停后，BH1750 连续采集五个有效样本，约需 1.02 秒，形成环境光基线。此时 `light_task.state == LIGHT_WAIT_RISE`。裁判应在基线建立后开灯；如果开灯过早，灯光可能被计入环境基线。
3. 相邻完成测量的照度增量达到 `max(20 lux, 环境基线 × 5%)`，且下一次测量仍保持该增量，认定检测到光源。单个尖峰、通信失败和饱和值不触发。
4. 四颗 LED 同步闪烁三秒，亮灭间隔各约 200 ms。遥控器蜂鸣器每秒短鸣一次，共三次，每次约 150 ms，整个告警窗口三秒。检测期间仍可人工水平移动。原高度/传感器故障 LED 优先级高于光源提示。
5. 人工移近光源。连续三个新测量值达到到位照度阈值，同时测距、光流、高度和倾角满足条件，锁定当前光流位置，进入 `LIGHT_HOLD`。这里按用户指定的照度判据“认定到位”，不是独立几何定位。
6. 到位悬停期间屏蔽横滚、俯仰、普通偏航、AUX1 接管和油门降落手势。仍接收遥控数据以监测失联；保留原低油门加左偏航紧急上锁、倾角保护和传感器故障处理。
7. 在照度仍达到阈值、位置与姿态稳定的条件下，连续悬停满三秒后进入 `LIGHT_COMPLETE`，自动恢复人工水平移动和普通偏航。继续保留原自动定高模式，避免从遥控器低油门突然切回手动油门。锁定期间的模式切换不会排队到结束后执行。
8. 本次起飞只执行一次到位悬停，完成后仍在灯下不会反复锁定；结束本次自动飞行、重新起飞后重新建立基线。原 AUX1 油门匹配接管、正常降落流程仍可在锁定窗口之外使用。

## 照度估算与校准

仅知道“5 W 白色 LED”和距离，无法确定实际 lux。电功率不能代替光通量或轴向光强，灯的透镜、光束分布及背景光都会影响读数。

按用户要求，先采用明确假设下的调试初值：假设 5 W 灯具输出 **500 lm**、朝上近似朗伯发光，感光面在轴线上正对光源，则光源贡献的照度约为：

`E = Φ / (π × h²) = 500 / (π × 0.8²) ≈ 249 lux`

因此默认 **到位阈值 = 起飞悬停时的环境基线 + 250 lux**。例如背景 300/400/500 lux 时，总照度阈值分别约为 550/650/750 lux。500 lm 是计算假设，250 lux 是估算参数，不是实际灯具数据，也不是实测合格阈值。

配置位于 [light_task_config.h](02主控源码/HAL/light_task_config.h)：

| 参数 | 当前值 | 用途 |
| --- | --- | --- |
| `LIGHT_ARRIVAL_DELTA_LUX` | 250 lux | 相对于环境基线的到位增量 |
| `LIGHT_THRESHOLD_CALIBRATED` | 0 | 明确标记尚未校准 |
| `LIGHT_RISE_MIN_LUX` / `LIGHT_RISE_RATIO` | 20 lux / 5% | 突增检测的初调值 |
| `LIGHT_ARRIVAL_CONFIRM_SAMPLES` | 3 | 三个独立测量值确认到位 |
| `LIGHT_HOLD_SECONDS` | 3 s | 连续稳定悬停计时 |
| `LIGHT_STABLE_FLOW_SPEED` | 1.0 | 供应商光流速度单位，不是 m/s |
| `LIGHT_HOLD_POSITION_ERROR` | 5.0 | 供应商光流位移单位，不是厘米 |

校准时，用最终安装姿态，将感光面放在实际标准灯轴线上、与发光面相距 0.8 m，保持环境照明一致，分别记录关灯和开灯后的稳定平均值。用“开灯值－关灯值”替换 `LIGHT_ARRIVAL_DELTA_LUX`，实测确认后再将校准标记设为 1。还需记录横向偏移时的照度，检查能否满足题目的定位要求。

阈值不能严格保证处于灯的正上方：高度下降、反射、旁侧光源也可能使照度越阈值。在 0.6～1.0 m 的允许高度范围内，读数与 0.8 m 标定值会有变化。当前按用户约定实施阈值触发，不宣称已验证定位精度。

原理参考：[ROHM BH1750 数据手册](https://www.mouser.com/datasheet/2/348/bh1750fvi-e-186247.pdf)、[NIST 光度学与反平方关系](https://www.nist.gov/pml/sensor-science/optical-radiation/realization-candela)。

## 硬件与通信

- BH1750 与激光/光流模块并联在原软件 I²C，总线为 PB6/SCL、PB7/SDA。
- BH1750：7 位地址 `0x23`，总线写/读地址 `0x46/0x47`。激光/光流：7 位地址 `0x62`，原代码继续使用 `0xC4/0xC5`，寄存器 `0x33`。
- BH1750 使用连续高分辨率模式 `0x10`，显式设置 MTreg=69，每约 204 ms 读取两个字节，`lux=raw/1.2`。转换期间不阻塞飞控，不把对同一数据的重复读取算作多个确认样本。
- BH1750 和原传感器的运行期 I²C 访问都位于同一飞控中断调度中，避免主循环与中断同时操作总线。
- 已从用户提供的遥控器程序确认蜂鸣器为 **PA12，高电平响**；保留开机音和按键音。光源告警窗口优先于按键音。
- 新遥控器每 20 ms 发送一次原 32 字节控制帧，随后切换到接收模式。保留八个通道的位置和校验方式；原程序越过八通道结构读取额外内存的行为已修正。
- 控制帧保留区 20～23 字节增加能力标记 `4C 54 01 A5`。飞控只对带该标记且已通过原有校验的控制帧回传状态，旧遥控器不会被强制切换到新协议。
- 飞控反馈头为 `AA B0 01 1B`，包含事件编号、告警已用毫秒、状态、照度与阈值，仍为 32 字节加和校验。重复反馈不会反复重启蜂鸣器的三秒计时；丢失个别状态帧由后续帧补充。
- 使用普通 NRF24L01 半双工收发，不依赖“+”型号的 ACK Payload 扩展。发送等待增加约 2.5 ms 超时，飞控无论发送成功或失败都恢复接收模式。无线往返延时、丢包及蜂鸣器实际节奏仍需两块板联调。

## 异常与计时

BH1750 失败或饱和不产生有效到位事件。锁定悬停时，短暂光照/测距/光流无效会清零稳定计时；持续约一秒则退出本次到位任务并恢复普通遥控权限，不记为完成。进入原降落或测距故障状态时也中止任务。十二秒仍无法累计连续三秒稳定悬停时中止，避免无限期屏蔽遥控。

保持位置、高度和姿态不稳定时，三秒计时从零重新累计，因此“从进入锁定到解除”的总时长可能超过三秒。紧急动作和故障处置可以提前终止任务。

修正了旧代码的双时钟计数问题：原来 1 ms SysTick 与 3 ms TIM1 都增加 `SysTick_count`。现在该变量只由 TIM1 更新，仍保持现有飞控约定的每计数 3 ms；延时和微秒接口使用独立的 1 ms 计数。主机检查实际调用两种中断，确认真实三秒对应 1000 个飞控 tick。

第一个脚本将实际 C 源码与硬件模拟组合，覆盖旧起飞/故障流程、BH1750 命令与转换周期、突增/尖峰/渐变、到位确认、遥控屏蔽与恢复、连续三秒、蜂鸣器重复包和晚到包、两种时钟、无线超时返回接收模式。最终检查数量以 [test_result.json](../04_编译与验证/BH1750_半自动光源_20261025/host_tests/test_result.json) 为准。

第二个脚本编译两个 STM32F103C8 工程，生成 AXF、HEX、BIN、MAP、源文件和固件哈希。两个工程的容量都按 64 KB Flash、20 KB RAM 限制链接。结果见 [build_result.json](../04_编译与验证/BH1750_半自动光源_20261025/arm_build/build_result.json)。原滤波库中未被当前控制调用的 `MovMiddle` 复制长度告警及旧汇编器弃用提示保留在日志中。

观察变量：`bh1750.raw/lux/valid/sample_id/errors`，`light_task.state/ambient_lux/arrival_lux/source_detected/stable_seconds/event_id`，遥控器 `remote_light_status`。

`light_task.state` 数值：0 等待起飞、1 建立基线、2 等待突增、3 人工接近、4 锁定悬停、5 完成并恢复遥控、6 本次任务中止。
