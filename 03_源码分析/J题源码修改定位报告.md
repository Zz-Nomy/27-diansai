# J题源码修改定位报告

整理日期：2026-10-20；验证更新：2026-10-21。依据：孙莹庞同学在QQ分享的资料、实际取得的20261001版主控源码，以及本地完整赛题。本文完成资料筛选和代码定位，给出修改方案；没有修改飞控源码、烧录固件或执行飞行测试。

## 主要结论

现有工程已有遥控起飞、定高和光流位置保持的基础控制，但不能直接视为完成J题。它锁定的是油门回中时的当前高度，并非固定0.8米；尚未找到自动一键起飞任务、地面光源识别、机载蜂鸣器提示、光照触发悬停或独立硬件急停的完整实现。

优先解决高度单位和测量有效性，再落实任务状态机。当前没有足够依据通过修改几个PID数值来认定定高故障已经解决。

## 三处必须先处理的问题

### 高度单位存在冲突

[协议图](../02_飞控源码与说明/01说明文档/外扩模块I2C通信协议.png)写“高度输出单位为cm”；但control.c第128行注释把3500解释为3500mm，其余量程与补偿参数也更接近按毫米使用。源码读取后没有显式单位转换。

因此，现阶段不能直接认定目标值应该填80或800。应先在地面用0.20m、0.50m、0.80m和1.00m等参考距离记录两个高度字节及解析后的原始值：若0.80m时约800则按毫米，约80则按厘米。进一步核对安装面的零点偏移，并把内部物理单位统一后再改任务目标。

统一为毫米后，任务目标为800mm，允许范围600～1000mm；如果保留原始厘米单位，对应目标为80、范围60～100。两套数值不能混用，也不能只改目标值而忽略原工程量程、速度和PID所依赖的单位。

### 零高度帧会留下旧值

[flow.c第118行](../02_飞控源码与说明/02主控源码/HARDWARE/flow.c:118)解析本次高度后，仅在high不为0时更新VL53L01_high；随后无论high是否为0，都把error_count清零。

静态代码路径表明：如果上次值为800，此后I²C通信一直成功、但高度字段持续为0，VL53L01_high会一直留在800，I²C失败计数也不会增加。现有控制层可能继续使用旧值。这是需要验证的代码风险，尚不能据此断言它就是本次样机故障的根因。

建议增加独立的raw_height、height_valid和last_valid_height_time，区分“通信成功”与“测距有效”；无效帧不能刷新有效时间戳。保持显示旧值时也必须标明失效，控制逻辑应核对并执行既定降级/接管规则，不能在没有方案时简单自动切断电机。

I²C连续读取失败时，该函数在前10次累加计数，第11次关闭定高和定点标志。按当前6ms调用周期，其调用跨度约66ms；这是基于调度代码的计算，尚未测量真实中断周期。成功读到零值与总线读取失败是两条不同路径。

### 光流质量不等于地面光源检测

协议第5个字节是光流图像质量分；[flow.c第50行](../02_飞控源码与说明/02主控源码/HARDWARE/flow.c:50)用squal大于30判断光流数据使用条件。它不是已经验证的地面5W光源照度或光敏阈值，不能把squal大于30直接当成J题“检测到光源”。

现有ADC.c也不能直接接入即用：ADC_DMA_Init未在ALL_Init中启用；GetADCValue的累加变量tmp没有初始化；ADC使用PB0/通道8，而CONFIG/TIM.c中的TIM3 LED输出也占用PB0。新增光敏采样前必须核对实际板卡与引脚用途，处理资源冲突，不能盲目把光敏器件接到PB0。

数据链：模块I²C五字节 → flow_get_data解析 → 高度融合及高度PID / 光流融合及位置PID → 姿态PID → MotorControl → TIM2 PWM。

I²C协议使用7位地址0x62，当前软件驱动传入的是含读写位的地址0xC4，寄存器为0x33，连续读5字节。现有驱动会发送addr和addr+1，不能只因协议写0x62就把调用中的0xC4直接替换掉。当前GPIO定义为PB6/PB7；接线还应对照实际板卡。

## 建议的修改与验证顺序

1. 地面测原始高度，解决单位冲突；记录零帧、无回波、I²C失败和有效帧的区别。
2. 增加有效标志与新鲜度，核对传感器异常时的接管规则，再处理0.8m任务目标。
3. 新增起飞任务状态机，协调现有解锁、MotorControl等待条件、目标高度和人工接管；完成前不能声称已具备一键起飞。
4. 核对光敏器件和机载蜂鸣器电路，处理ADC/LED引脚冲突，再增加光源检测及两类声光事件管理。
5. 用光源到位事件切换位置保持，防止遥控AUX1分支把任务模式反向切走；核对实际稳定后累计至少3秒。
6. 统一LED任务状态显示，并补独立硬件急停。
7. 先完成地面数据与输出检查，再由队员做题目规定的飞行验收，并补设计报告中的真实测量结果。
