# 飞控代码阅读摘要

阅读与整理日期：2026-10-25。依据本地供应商20261001版工程及既有验证记录。此文为阅读结论，不是代码修改或飞行测试报告。

## 工程和执行结构

主控为STM32F103C8，Keil工程目标Target 1，设备包记录Keil.STM32F1xx_DFP.2.4.1。

| 文件/函数 | 主要作用 |
| --- | --- |
| USER/main.c：main | 初始化后轮询上位机通信、遥控解析和LED |
| USER/INIT.c：ALL_Init、pid_param_Init | 初始化I²C、MPU6050、NRF24L01、电机/LED PWM和调度定时器；设置PID参数 |
| USER/scheduler.c：TIM1_UP_IRQHandler | 3ms执行IMU采样、姿态PID和电机输出；6ms执行姿态解算、高度PID和模块读取；24ms执行光流融合与位置PID |
| HARDWARE/flow.c：flow_get_data | 从地址0xC4、寄存器0x33读5字节，解析高度、X/Y有符号光流数据和质量分 |
| HAL/control.c：HeightPidControl | 高度外环产生垂直速度目标，速度内环产生油门修正 |
| HAL/control.c：FlowPidControl | 位置外环和速度内环产生横滚/俯仰目标 |
| HAL/control.c：FlightPidControl | 姿态角外环、角速度内环，计算姿态修正 |
| HAL/control.c：MotorControl | 混合油门与姿态输出，写入TIM2四路PWM |
| HAL/remote.c：RC_Analy、remote_unlock | 解析遥控通道，处理模式切换、解锁和上锁 |
| HARDWARE/LED.c：PilotLED | 根据解锁、定高、定点标志刷新LED |

数据链：激光/光流读取 → 高度与位置控制 → 姿态控制 → 电机混控 → TIM2 PWM。调度中的高度PID先于本周期flow_get_data运行，因此使用此前取得的数据。

## 已有行为与关键问题

1. 解锁采用油门低→高→低，解锁时关闭定高和定点；电机输出仍等待油门超过1100。尚无完整的一键起飞任务。
2. AUX1变化会同时切换定高和定点标志。定高时油门回中会把当前高度写入目标；上/下推油门改为速度控制，尚未固定0.8m。
3. 定高入口将thr_hold设为500。高度、速度与电机输出需整条链核对，不能只改目标值或PID。
4. 成功读取零高度帧时不更新VL53L01_high，但清零error_count，可能持续沿用旧高度。连续总线失败在第11次关闭定高/定点，恢复通信不自动重开；已有主机模拟复现。
5. 协议图和代码注释对高度单位存在冲突。必须用0.20、0.50、0.80、1.00m参考距离实测，再确定0.8m对应80或800，并统一相关量程和控制量。
6. 光流质量squal不是光照强度；不能用它替代光敏传感器。ADC初始化尚未接入ALL_Init；ADC示例使用PB0，与当前LED PWM引脚重叠，GetADCValue中的累加变量也未初始化，接入前需核对修正。
7. LED刷新会主动覆盖LED.status，新任务状态应统一接入指示逻辑。尚未发现完整的机载蜂鸣器、光源触发悬停3秒和独立硬件急停实现。
8. pidUpdate的积分限幅与输出限幅代码被注释。是否导致实际问题尚无实测证据，后续修改需结合输出饱和和飞行记录验证。
